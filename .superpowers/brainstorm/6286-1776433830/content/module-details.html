方案A：运行时反射修改

  • 通过 SDK 直接用反射改 View 的 margin/padding
  • 改完立即生效，截图校验
  • ✅ 快，循环紧凑
  • ❌ 改的是内存状态，重启丢失
  • ❌ 不能改布局文件
★ 推荐 / 需确认

方案B：修改源码 + 重新编译

  • AI 直接改 XML/Kotlin 源码
  • 重新 build → 安装 → 截图校验
  • ✅ 改动持久，最终产出可用代码

  • ❌ 收敛慢

📐 模块1 无头浏览器方案 方案对比

❌ 纯 BeautifulSoup

  • 只解析 HTML 结构
  • 拿不到渲染后坐标
  • flex/grid 布局后位置未知
  • 成本极低
  • 不够用
★ 推荐

✅ Playwright（无头）

  • 真实渲染，拿到 getBoundingClientRect
  • 一次性运行，不是常驻服务
  • pip install playwright 即可
  • 首次安装约 100MB Chromium
  • 运行一次 ~2-5 秒

🟡 Selenium

  • 同样可以拿坐标
  • 需要本地安装浏览器
  • 依赖 chromedriver 版本
  • 维护成本比 Playwright 高
关于使用成本：Playwright 只在「预处理阶段」运行一次，不是每次校验都跑。
预处理完成后输出 JSON，之后所有对比都基于 JSON，不再需要浏览器。
额外成本：首次安装约 100MB，单次运行 2-5 秒，可接受。
